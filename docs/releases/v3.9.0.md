# chb v3.9.0

Release date: 2026-07-30

A minor release that turns `chb odoo sync` into a real one-command loop, makes
the metadata/partner repair work retroactively, fixes three data-correctness
bugs that were silently hiding transaction descriptions, and adds `chb serve` —
a read-only, mobile-friendly web UI to review transactions.

## Highlights

### `chb odoo sync` — one command, all journals up to date

`chb odoo sync` was a deprecated alias for `chb odoo pull`. It is now the full
loop. For every non-archived account linked to an Odoo journal, in journal order:

1. **pull** the account's source → local (Stripe payouts, on-chain transfers),
   fetching Monerium order metadata and re-generating the local view so new
   lines carry a real description,
2. **push** the new local transactions into the Odoo journal,
3. **reconcile** them against open invoices/bills, then **categorise** whatever
   found no document onto the GL account its rules resolve to (suspense-only, so
   manual work is never reverted).

Odoo-side documents (invoices, bills, partners) are refreshed first, because the
reconcile matcher works off that cache — without it every new line stays on
suspense. Prints one row per journal plus a closing tally.

```
chb odoo sync              # full loop
chb odoo sync --local      # skip the remote fetch, work from local files
chb odoo sync --dry-run    # preview; no writes to Odoo
chb odoo sync --since 20260701
```

`odooSourceOfTruth` journals (KBC) are pull + reconcile only — Odoo owns their
lines, so chb never pushes into them.

### Retroactive metadata + partner repair

- **`chb odoo journals <id> fix --metadata [--since]`** runs *only* the metadata
  step: it re-derives `payment_ref` + narration on existing lines from the latest
  local cache. It now also **repairs reconciled lines** (unreconcile → draft →
  write → repost), restoring the counterpart GL account afterwards so a relabel
  never silently un-categorises a line. Lines matched to a real invoice/bill are
  still left alone.
- The same pass now **links or creates the right partner** from the provider's
  counterpart — a Monerium order's IBAN + name, or an on-chain address. It only
  fills lines that have no partner, and never invents a nameless one.
- **`chb odoo journals <id> reconcile --since YYYYMMDD`** windows a reconcile to
  recent lines instead of re-scanning years of settled history.

### Data-correctness fixes

Three bugs conspired to leave on-chain transfers labelled `mint EURe` / `burn EURe`
with no partner, even though Monerium had the description all along:

- **Monerium orders placed late in a month were dropped.** The sync short-circuited
  on "newest order id unchanged", but an order placed at 21:59 UTC on the 30th is
  not the global newest, so it never reached the month file. The save loop was also
  clamped to the *blockchain* fetch window, skipping months outside it. Months are
  now compared by content, and every month the API returns is considered.
- **`buildUniqueImportID` corrupted the id for reloaded blockchain txs.** `TxHash`
  is internal and `omitempty`, so after a reload from `transactions.json` the code
  fell back to `tx.ID` — the NIP-73 URI `ethereum:100:tx:0x…` — producing an id
  that never matched the clean one Odoo stored. Metadata, reconcile and categorise
  all silently skipped those lines. It now falls back to `ProviderID` (the clean
  hash) first.
- **Narration parsing ignored Odoo's HTML wrapper.** Odoo returns narration as
  `<p>{…}</p>`; the raw `json.Unmarshal` failed for every round-tripped line, so
  comparisons saw "empty" and re-flagged the same lines as stale forever. The
  wrapper is now stripped (with an entity-unescape fallback).

Also: `chb odoo sync` re-pulls the full invoice/bill history once when the local
cache holds no open candidates (or fewer than 10 documents overall) — a
freshly-bootstrapped namespace could otherwise reconcile against nothing.

### `chb serve` — read-only transaction review UI

A mobile-first web UI to review the latest transactions across all journals,
designed to be exposed over Tailscale.

- **Transactions** grouped by date, with partner, amount, matched-document
  indicator, memo and colour-coded GL account; filter chips with shortcuts for
  savings / checking / stripe.
- **Transaction page** (shareable URL) with the linked bill/invoice, a link to
  the block explorer or Stripe dashboard, and — when nothing is matched —
  ranked **reconcile candidates** plus a deep link to Odoo's reconciliation view.
- **Partner pages** (total txs, volume in/out, latest txs) and **GL account
  pages** (balance, debit, credit, latest entries).
- **Settings** to switch database and select journals, persisted in
  localStorage; a banner warns when the database name contains `test`.
- **Laptop/iPad**: master–detail split view with an aligned, table-like list.

Strictly read-only: the server only ever issues `search_read` / `read_group`
calls against a whitelisted set of models, and the database must be in an
allowlist (`ODOO_SERVE_DBS`, default `commonshub,commonshub-test`).

```
chb serve                            # http://127.0.0.1:8787
chb serve --addr 100.x.y.z:8787      # bind to the Tailscale IP
tailscale serve --bg 127.0.0.1:8787  # or expose over Tailscale with TLS
```

## Upgrade Notes

- `chb odoo sync` now **writes** (push + reconcile + categorise). If you were
  using it as an alias for the read-only fetch, use `chb odoo pull` instead.
- After upgrading, run `chb odoo journals <id> fix --metadata --since <date>` on
  blockchain journals to back-fill descriptions and partners on lines pushed
  before the import-id fix.
- `chb serve` needs `ODOO_LOGIN` / `ODOO_PASSWORD` in `settings/config.env`. It
  binds to `127.0.0.1` by default; exposure is delegated to Tailscale.
