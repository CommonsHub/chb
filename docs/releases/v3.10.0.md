# v3.10.0 — shared config ships with the binary; private IBAN rules stay local

## Why

The embedded defaults (`cmd/defaults/` → seeded into
`$APP_DATA_DIR/settings/`) had drifted months behind the operator's live
config: the live `rules.json` had 192 rules vs 63 embedded, plus newer
categories, collectives, the `door` Discord channel, and an
`odoo-analytic-accounts.json` that wasn't shipped at all. A fresh install got
a config that no longer matched how the org actually categorizes.

Simply committing the live files was not an option: 58 rules match on
counterparties' concrete IBANs (renters, coworking members, consultants) and
this repo is public.

## What changed

- **All shareable config is now embedded and committed**: `settings.json`
  (incl. the `door` channel), `categories.json`, `collectives.json`,
  `odoo-journals.json` (refreshed seed), `rules.json`, and the new
  `odoo-analytic-accounts.json`. Every machine converges on the same config
  through the existing conffile-style reconciler.
- **New `rules.local.json`** (`$APP_DATA_DIR/settings/`, mode 0600): holds
  every rule matching a concrete third-party IBAN. Never committed, never
  embedded. Glob IBAN patterns (`DE*`) and IBANs deliberately published in
  the embedded default (Stripe's collection IBAN) stay in the shared file.
- **Splice marker `{"include": "rules.local.json"}`** in `rules.json` records
  where the private block sits, because rule order is load-bearing
  (specific rules → IBAN heuristics → catch-alls). `LoadRules` merges at the
  marker; `SaveRules` re-splits on every save, so `chb rules add` with an
  IBAN automatically lands in the local file. Old binaries read the marker as
  a match-nothing no-op.
- **Automatic migration**: a legacy monolithic `rules.json` is split on first
  run; the marker is inserted at the median position of the extracted rules
  (where the IBAN block sat).

## Verification

Full `chb generate --history` over a copy of the production data dir, old
binary + monolithic rules vs new binary + split rules: **0 semantic diffs**
across all 604 generated files (39 months), timestamps aside.

## Upgrading another machine

1. Install the v3.10.0 binary.
2. Run any `chb` command once: the migration moves IBAN rules to
   `rules.local.json` and the reconciler adopts the new shared defaults
   (files you edited locally surface as pending updates in `chb settings`).
3. `config.env` (secrets) is untouched and stays local, as before.
