# v3.9.1 — never push a bare "mint EURe" again

Patch release. `chb odoo sync` could create statement lines for EURe
mints/burns before their Monerium order metadata was fetched — the journal
then showed bare `mint EURe` lines with no partner and nothing to reconcile
against, needing a manual `fix --metadata` pass. This release makes that
impossible.

## The hold guard

Every EURe mint/burn corresponds to a Monerium order whose memo carries the
human description — often the exact invoice ref the reconciler needs
(`MEM/2026/00070`, `S00132`). The push now refuses to create a line for a
mint/burn whose enrichment hasn't landed:

```
⚠ 4 mint/burn txs held back — Monerium metadata not fetched yet (mint/burn without memo)
  cause: MONERIUM_CLIENT_ID/MONERIUM_CLIENT_SECRET not set
  fix the Monerium fetch, then re-run: chb accounts pull savings --verbose
```

Held txs are reported in the `chb odoo sync` per-journal summary
(`⚠ 4 txs held (awaiting Monerium metadata)`) and suppress the push cursor,
so they are retried on every run until the metadata arrives — then pushed
with the proper memo, partner and reconciliation in one go.

The fetch layer now records *why* orders were missing (credentials not set,
auth failure, API error) so the hold message names the cause instead of
leaving a silent warning buried in sync output.

## Self-healing enrichment

A Monerium order can land *after* its on-chain tx was already cached (the
order stays pending while the bank leg settles, or an earlier run fetched
the chain but not the orders). Bulk `chb sync` only re-fetched orders when
the blockchain changed — so those txs stayed `mint EURe` forever unless you
ran an explicit account pull. `chb sync` now re-fetches orders whenever the
recent months contain an un-enriched mint/burn, until they heal.

## Also

- **Polygon enrichment gap**: a pull scoped to a polygon EURe account
  (`savings-polygon`) never fetched Monerium orders at all — the chain gate
  only listed gnosis. Polygon and ethereum now pass through.
- `chb sync` closes with the current verb: `To update the Odoo journals:
  chb odoo sync` (was pointing at the retired `chb odoo journals push`).

## Upgrade

The guard lives in the push path, so it protects whichever machine runs
`chb odoo sync` — update the binary everywhere you push from.
